# 打包与构建

本文讲**产出什么、怎么产出**：发布产物有哪些、目录怎么组织、安装器怎么打。

- 流水线触发与步骤：[CI/CD 配置](04-CICD配置.md)
- 版本号从哪来、怎么发：[发布流程](05-发布流程.md)

最后核对：2026-11-14。

---

## 1. 产物清单

| 产物 | 说明 |
|---|---|
| `LanMountainDesktop.Launcher.exe` | 启动器，NativeAOT 单文件，放在发布根 |
| `LanMountainDesktop.AirAppRuntime.exe` | AirApp 运行时，放在发布根 |
| `LanDesktopPLONDS.installer.exe` | 在线安装器 / 维护程序（同一个 exe，`--apply-update` 是维护入口），AOT |
| `app-{version}/` | 主程序部署目录，内含 `LanMountainDesktop.exe` 与 `.current` |
| `files-windows-{arch}.zip` | 完整载荷（排除 `.partial` / `.destroy`） |
| `changed-windows-{arch}.zip` | 增量载荷（见 [增量更新实现](02-增量更新实现.md)） |
| `LanMountainDesktop-Setup-{version}-{arch}.exe` | Inno Setup 图形安装包 |

非 Windows 侧目前只有 Linux 打包元文件（Flatpak / AppImage / linglong），**没有脚本化的产物**。

## 2. 发布目录组织

```
publish/windows-{arch}/
├── LanMountainDesktop.Launcher.exe
├── LanMountainDesktop.AirAppRuntime.exe
├── LanDesktopPLONDS.installer.exe
└── app-{version}/
    ├── .current
    ├── LanMountainDesktop.exe
    └── ...
```

顺序由 `release.yml` 决定：**Publish Launcher(AOT) → Publish 主程序 → Publish AirAppRuntime → Publish AirAppHost → Publish 维护安装器(AOT)**，然后做目录重组，最后产出载荷 zip。

**这个结构不是随意的**：根目录放"跨版本必须稳定"的东西（启动器、运行时、安装器），版本目录放"随版本变"的东西。理解这一点就理解了为什么 Launcher 一改就必须走 `requiresCleanInstall`。

---

## 3. 安装包

- 唯一图形安装器是 `install/LanDesktopPLONDS.installer`，用 Inno Setup，源在 `desktop/LanMountainDesktop/installer/LanMountainDesktop.iss`。
- 产物命名 `LanMountainDesktop-Setup-{version}-{arch}{suffix}.exe`。
- 默认装到 `{autopf}`，`PrivilegesRequired=admin`。
- `[Run]` 里的 `Add-AppxPackage -Register ...WindowsIdentity\AppxManifest.xml` **不是应用打包**，只是注册通知身份——不要据此认为存在 MSIX 分发。

另有独立的二次安装器 `install/LanDesktop.MewInstaller`（AOT，`MewUIBackend=Direct2D`），由 `installer-build.yml` 负责。

## 4. 脚本现状（重要）

`scripts/` 下的更新/打包脚本并非都可用：

| 脚本 | 状态 |
|---|---|
| `Publish-AOT.ps1` | 可跑（Launcher AOT），但**未接 CI** |
| `Generate-DeltaPackage.ps1` | 产出旧格式 `files.json`（`{FromVersion, ToVersion, GeneratedAt, Files[]}`），非现行清单格式 |
| `Sign-FileMap.ps1` | 转调 `Plonds.Tool sign`——**该子命令不存在**，运行会以 "Unknown command" 失败 |
| `Generate-PlondsArtifacts.ps1` | 转调 `Plonds.Tool generate`——**同样不存在** |
| `Publish-Plonds.ps1` | 无 workflow 引用 |

`Plonds.Tool` 实际提供的命令是：`build-delta`、`build-delta-from-commits`、`publish-s3`、`enrich-manifest`、`pack-payload`。

**结论：增量产物的正规生成路径是 CI 的 `plonds-comparator.yml` + `plonds-uploader.yml`，不是本地脚本。** 本地能跑的只有 `Publish-AOT.ps1`。

## 5. 版本号注入

版本真源是 **git tag**，构建期由脚本写进代码文件：

```
tag v1.2.3
  → Set-ReleaseVersion.ps1 写 Directory.Build.props 的 <Version>
                            写三个 csproj 的 <Version>
                            改两个 app.manifest 的 assemblyIdentity/@version
  → release.yml 再用 -p:Version / -p:AssemblyVersion 统一注入
```

`Directory.Build.props` 里的默认值是 `0.0.0-dev`（占位，不是真实版本）。

## 6. 签名

| 环节 | 现状 |
|---|---|
| Authenticode | **默认只报告**，`LANMOUNTAIN_INSTALLER_REQUIRE_SIGNED=1` 才强制 |
| CI 代码签名 | **没有**。workflows 里没有 signtool 或签名脚本调用 |
| 清单签名 | 见 [更新系统架构](01-更新系统架构.md) 第 8 节 |

也就是说：**当前发布的二进制不做 Authenticode 签名**，用户在安装时看到的"未知发布者"是这个现状的直接结果，不是配置失误。

# 创建第一个轻应用

本文从模板开始，做一个显示问候语的桌面组件，再加一个窗口，最后装进宿主。

前置条件见[环境准备](01-环境准备.md)。

## 1. 生成工程

```bash
dotnet new lmd-airapp -n Acme.HelloAirApp
cd Acme.HelloAirApp
```

生成的文件：

```
Acme.HelloAirApp/
├── Acme.HelloAirApp.csproj
├── airapp.json              # 清单，id 自动取项目名
├── AirApp.cs                # 入口
├── MyComponent.cs           # 桌面组件
├── MyWindow.cs              # 窗口轻应用
├── Localization/
│   ├── zh-CN.json
│   └── en-US.json
└── README.md
```

模板会把 `airapp.json` 的 `id` 和 `entranceAssembly` 自动改成项目名，
不会和别的轻应用撞 id。

## 2. 入口类

入口类必须标注 `[AirAppEntrance]`，并实现 `IAirApp`（通常继承 `AirAppBase`）。
**一个程序集里只能有一个入口类**，多于一个时宿主会拒绝加载。

```csharp
using LanMountainDesktop.AirAppSdk;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

namespace Acme.HelloAirApp;

[AirAppEntrance]
public sealed class HelloAirApp : AirAppBase
{
    public override void Initialize(HostBuilderContext context, IServiceCollection services)
    {
        // 所有贡献都在这里注册。宿主在初始化完成后从 services 中读取。
        services.AddAirAppComponent<HelloComponent>(
            "hello-widget",
            "问候组件",
            options =>
            {
                options.Description = "显示一句问候语";
                options.Category = "Custom";
                options.IconKey = "AppGeneric";
                options.MinWidthCells = 2;
                options.MinHeightCells = 2;
            });

        services.AddAirAppWindow<HelloWindow>("hello-window", "问候窗口");
    }

    public override Task OnStartedAsync(IAirAppRuntimeContext context)
    {
        context.Logger.Info("HelloAirApp started.");
        return Task.CompletedTask;
    }

    public override Task OnStoppingAsync()
    {
        return Task.CompletedTask;
    }
}
```

三个生命周期方法的职责边界很明确：

| 方法 | 何时调用 | 能做什么 |
|---|---|---|
| `Initialize` | 构建服务容器时 | **只做注册**。此时还没有 `RuntimeContext`，不要访问文件或网络 |
| `OnStartedAsync` | 服务容器就绪后 | 拿到 `IAirAppRuntimeContext`，做需要运行时服务的初始化 |
| `OnStoppingAsync` | 宿主停止时 | 释放资源、落盘 |

注册**只能**在 `Initialize` 里通过 `IServiceCollection` 完成，
没有「运行期再注册一个组件」的 API。

## 3. 桌面组件

组件就是一个 Avalonia `Control`。构造函数由 `ActivatorUtilities` 调用，
可以接收 `AirAppComponentContext` 以及任何你在 `Initialize` 里注册过的服务。

```csharp
using Avalonia.Controls;
using Avalonia.Layout;
using LanMountainDesktop.AirAppSdk;

namespace Acme.HelloAirApp;

public sealed class HelloComponent : UserControl
{
    public HelloComponent(AirAppComponentContext context)
    {
        var localizer = AirAppLocalizer.Create(context);

        var openButton = new Button
        {
            Content = "打开窗口",
            HorizontalAlignment = HorizontalAlignment.Center
        };
        openButton.Click += async (_, _) => await context.OpenWindowAsync("hello-window");

        Content = new StackPanel
        {
            Spacing = 8,
            HorizontalAlignment = HorizontalAlignment.Center,
            VerticalAlignment = VerticalAlignment.Center,
            Children =
            {
                new TextBlock
                {
                    Text = localizer.GetString("greeting", "你好，阑山桌面"),
                    HorizontalAlignment = HorizontalAlignment.Center
                },
                openButton
            }
        };
    }
}
```

`AirAppComponentContext` 提供的东西：

| 成员 | 用途 |
|---|---|
| `ComponentId` / `PlacementId` | 组件标识与这一个实例的放置标识 |
| `CellSize` | 当前网格单元像素尺寸，用于自适应排版 |
| `AirAppDirectory` / `DataDirectory` | 包目录（只读）与数据目录（可写） |
| `Appearance` | 主题快照、圆角解析、主题变更事件 |
| `CornerRadiusTokens` | 圆角令牌，等价于 `Appearance.Snapshot.CornerRadiusTokens` |
| `AirAppSettings` | 组件级设置读写，按 `ComponentId` + `PlacementId` 分实例 |
| `Services` | 本轻应用的服务容器 |
| `Properties` | 宿主属性，键见 `AirAppHostPropertyKeys` |
| `OpenWindowAsync(windowId)` | 打开本轻应用声明的窗口 |

注意区分两个目录：`AirAppDirectory` 是包所在目录，升级会被覆盖，不要往里写；
用户数据一律写 `DataDirectory`。

## 4. 窗口轻应用

窗口由独立的 AirAppHost 进程承载，实现 `IAirAppWindow` 并暴露 `Content`：

```csharp
using Avalonia.Controls;
using LanMountainDesktop.AirAppSdk;

namespace Acme.HelloAirApp;

public sealed class HelloWindow : AirAppWindowBase
{
    public HelloWindow()
    {
        Title = "问候";
        Content = new TextBlock { Text = "这是一个独立进程里的窗口" };
    }
}
```

因为跨进程，窗口和组件**不共享内存中的对象**。两者之间传数据要走持久化
（`DataDirectory`）或宿主提供的 IPC，不要指望静态字段。

## 5. 构建

```bash
dotnet build -c Release
```

构建结束后项目根目录会出现 `Acme.HelloAirApp.1.0.0.laapp`。
这一步由 SDK 的 MSBuild targets 自动完成，并强制校验：

- `airapp.json` 存在于构建输出
- 入口程序集存在
- `.deps.json` 存在

任何一项缺失都会让构建失败，避免产出宿主加载不了的包。

## 6. 装进宿主

把 `.laapp` 复制到：

```
%LOCALAPPDATA%\LanMountainDesktop\Extensions\AirApps\
```

重启宿主，在组件库里应当能看到「问候组件」。

## 7. 开发期调试

每次改动都重新打包很慢。开发时直接让宿主指向构建输出目录：

```bash
LanMountainDesktop.exe --dev-airapp "D:\code\Acme.HelloAirApp\bin\Debug\net10.0"
```

也可以用环境变量 `LMD_DEV_AIRAPP`。开发期覆盖的优先级高于散放清单和 `.laapp` 包，
所以同 id 时会盖掉已安装的正式版本。

调试断点：用 IDE 附加到 `LanMountainDesktop.exe`（组件）或
`LanMountainDesktop.AirAppHost.exe`（窗口）。

## 常见问题

**加载失败，日志提示缺少 `.deps.json`**
项目没开 `EnableDynamicLoading`，或用了自定义打包脚本。用 SDK 自带的打包 target。

**加载失败，提示 API 版本不匹配**
`airapp.json` 的 `apiVersion` 主版本与宿主 SDK 不一致。宿主只接受主版本相同的轻应用。

**组件没出现在组件库**
检查 id 是否与其他轻应用重复——宿主对重复 id 只保留先发现的那个，其余记为加载失败。

**类型加载异常，提示 Avalonia 版本冲突**
工程里显式引用了与 SDK 不同版本的 Avalonia。删掉自己的 Avalonia 引用，由 SDK 传递。

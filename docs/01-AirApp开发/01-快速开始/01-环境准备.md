# 环境准备

## 需要什么

| 项 | 要求 |
|---|---|
| .NET SDK | 10.0（仓库 `global.json` 固定 `10.0.103`，`rollForward: latestFeature`） |
| 操作系统 | Windows 10+ / Linux / macOS |
| IDE | Visual Studio 2022+、Rider 或 VS Code + C# Dev Kit |
| 阑山桌面宿主 | 用于调试加载轻应用 |

验证 SDK：

```bash
dotnet --list-sdks
```

## 配置包源

`LanMountainDesktop.AirAppSdk` 发布在 **GitHub Packages**。
GitHub Packages 的 NuGet 源即使托管公开包，**还原时也必须提供凭据**，
所以第一步是配置认证，否则 `dotnet restore` 会直接 401。

### 1. 申请 token（只有本地开发需要）

在 GitHub 创建一个 classic Personal Access Token，勾选 `read:packages`。
只读包不需要其他权限。**CI 里不需要这张 token**——见下面第 3 节。

### 2. 写入 NuGet.config

在轻应用项目目录放一份 `NuGet.config`。**凭据不要写死在这里**——用环境变量占位符引用，
文件本身就可以提交（本仓库六个示例轻应用就是这么做的，一份文件同时说清"源地址"和"凭据放在哪个槽"）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
    <add key="lanmountain" value="https://nuget.pkg.github.com/wwiinnddyy/index.json" />
  </packageSources>
  <packageSourceCredentials>
    <lanmountain>
      <add key="Username" value="%LANMOUNTAIN_PACKAGES_USER%" />
      <add key="ClearTextPassword" value="%LANMOUNTAIN_PACKAGES_TOKEN%" />
    </lanmountain>
  </packageSourceCredentials>
</configuration>
```

本地开发把这两个变量设进环境（PAT 需 `read:packages`）：

```bash
export LANMOUNTAIN_PACKAGES_USER=<你的GitHub用户名>
export LANMOUNTAIN_PACKAGES_TOKEN=<你的PAT>      # Windows 用 setx 或 $env:
```

> **为什么不用 `dotnet nuget add source`**：上面这份 `NuGet.config` 已经登记了名为 `lanmountain` 的源，
> 再 `add source --name lanmountain` 会直接失败——实测报
> `The name specified has already been added to the list of available package sources.`
> （这条不需要仓库权限也会撞，因为它校验的是合并后的源列表）。
> 只想用用户级配置的话，就别在项目里放这份 `NuGet.config`。
>
> 变量没设时 `%VAR%` 会被替换成空串，还原报的是
> `Value cannot be null or empty string. (Parameter 'password')`——
> 看着像包丢了，其实缺的是凭据。

### 3. CI 中的配置：用工作流自带的 `GITHUB_TOKEN`，不需要 PAT

`permissions` 里给 `packages: read`，然后把那两个环境变量指向 job 自带的 `GITHUB_TOKEN`，
**不需要配任何仓库 secret，也不要再跑改配置文件的步骤**：

```yaml
permissions:
  contents: read
  packages: read

env:
  # 源地址与凭据槽都只在 NuGet.config 里说一次，这里只注入变量值。
  LANMOUNTAIN_PACKAGES_USER: ${{ github.actor }}
  LANMOUNTAIN_PACKAGES_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

这条是**实测**出来的，不是照抄文档的推测（SamplePlugin run `36178925559`，同一个 job、同一份
`NuGet.config`，两次还原各用一个全新的 `--packages` 目录加 `--no-cache`，以免 NuGet 的 http-cache
把第二次还原喂成假绿）：假 token 报 `NU1301 → 401 (Unauthorized)`，换成 `GITHUB_TOKEN` 就还原成功、
包落进 `lanmountaindesktop.airappsdk/1.0.1`。HTTP 层同一个 nupkg 地址：匿名 `401`，`GITHUB_TOKEN` 作
密码 `200`（用户名 `x-access-token` / `github-actions` / `github.actor` 三个都通）。

> **改正一条此前写错的事实**：本节原来写着"`GITHUB_TOKEN` 只对本仓库的包有权限，跨仓库读取需要
> 一张 `read:packages` 的 PAT"。那句是错的——公开包的跨仓库读取 `GITHUB_TOKEN` 就能做。
> 需要 PAT 的只有**本地开发**（以及私有包的 CI 读取，本仓库未实测，别当成已验证）。

顺带一句为什么这里没有"判空守卫"：`GITHUB_TOKEN` 在 workflow 里恒不为空，能坏的只剩
`permissions` 没写 `packages: read`，而那时还原自己会报 `NU1301 / 401`，看错误码就够了。

> 曾经用过的两种写法都量过、都不行：`add source`（与同名源冲突，见上）；
> `dotnet nuget update source … --store-password-in-clear-text` 在 Linux runner 上报
> `Password encryption is not supported on .NET Core for this platform.`
> （这个子命令不吃"明文"那个开关）。用上面注入环境变量的写法就绕开了这两层。

### 备选：本地源

不想配置 token 时，可以克隆宿主仓库自行打包：

```powershell
git clone https://github.com/wwiinnddyy/LanMountainDesktop.git
cd LanMountainDesktop
./scripts/Pack-AirAppPackages.ps1 -Configuration Release -OutputPath ./artifacts/nuget
```

然后把 `artifacts/nuget` 作为本地文件夹源加入 `NuGet.config`。

## 安装模板

```bash
dotnet new install LanMountainDesktop.AirAppTemplate
```

确认安装成功：

```bash
dotnet new list lmd-airapp
```

应当列出 `LanMountainDesktop AirApp / lmd-airapp / [C#]`。

## 工程结构

模板生成的工程只需要一个 `PackageReference`：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <Version>1.0.0</Version>
    <EnableDynamicLoading>true</EnableDynamicLoading>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="LanMountainDesktop.AirAppSdk" Version="1.0.0"
                      ExcludeAssets="runtime" PrivateAssets="all" />
  </ItemGroup>
</Project>
```

几个关键点：

- **不需要**显式引用 Avalonia。SDK 已经传递引用，版本由 SDK 决定，
  自己再钉一个不同版本的 Avalonia 会导致加载期类型冲突。
- `ExcludeAssets="runtime"` `PrivateAssets="all"`：SDK 程序集由宿主提供，
  不要打进 `.laapp`，否则会与宿主的同名程序集冲突。
- `EnableDynamicLoading` 让构建产出完整的 `.deps.json`，宿主强制要求它存在。
- **不需要**手写打包脚本。SDK 的 MSBuild targets 会在构建后自动产出
  `<AssemblyName>.<Version>.laapp`，并校验 `airapp.json` 与 `.deps.json`。

## 清单文件

`airapp.json` 放在项目根目录，构建时自动复制到输出并打进包。
这是宿主识别轻应用的唯一入口，字段以 SDK 的 `AirAppManifest` 为准：

```json
{
  "id": "Acme.WeatherAirApp",
  "name": "天气",
  "description": "显示实时天气的桌面组件",
  "author": "Acme",
  "version": "1.0.0",
  "apiVersion": "1.0.0",
  "entranceAssembly": "Acme.WeatherAirApp.dll",
  "sharedContracts": [],
  "runtime": { "mode": "in-proc" },
  "components": [
    { "id": "weather-now", "name": "实时天气", "defaultWidth": 2, "defaultHeight": 2 }
  ],
  "windows": [],
  "permissions": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一。重复时宿主只加载第一个并记录冲突 |
| `name` | 是 | 显示名称 |
| `entranceAssembly` | 是 | 入口程序集文件名，重命名项目后必须同步 |
| `apiVersion` | 否 | 缺省取宿主当前 API 版本；填写时主版本必须匹配 |
| `description` / `author` / `version` | 否 | 元数据 |
| `sharedContracts` | 否 | 共享契约引用 |
| `runtime.mode` | 否 | 目前仅 `in-proc` 生效 |
| `components` / `windows` | 否 | 声明贡献内容，供市场展示 |
| `permissions` | 否 | 预留 |

`AirAppManifest` 不认识的字段会被忽略，不要指望 `icon`、`homepage`、
`minHostVersion` 之类的字段生效——这些属于**市场条目**，不属于清单。

## 安装位置

宿主从下面这个目录发现轻应用（`AppDataPathProvider.GetDataRoot()` 下）：

```
Windows: %LOCALAPPDATA%\LanMountainDesktop\Extensions\AirApps\
```

发现规则：

1. 递归扫描 `*.laapp` 包，读取包内的 `airapp.json`
2. 递归扫描散放的 `airapp.json`
3. `--dev-airapp` 指定的开发期覆盖

优先级 `--dev-airapp` > 散放清单 > `.laapp` 包，同 id 先到先得。
`.runtime` 子目录是解包暂存区，会被跳过。

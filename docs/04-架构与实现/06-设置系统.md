# 设置系统

设置系统负责配置的作用域划分、读写、变更通知、界面注册与历史迁移。本文讲**机制与约束**；轻应用作者视角见 [设置系统](../01-AirApp开发/02-核心概念/03-设置系统.md)。

代码位置：`desktop/LanMountainDesktop/Services/Settings/`、`Services/AppSettingsService.cs`、`Services/LauncherSettingsService.cs`；契约在 `airapp/LanMountainDesktop.AirAppSdk/`。

最后核对：2026-11-14。

---

## 1. 作用域与落盘位置

`AirAppSettingsScope` 四个取值，各自落到不同存储：

| 作用域 | 值 | 落盘 | 实现 |
|---|---|---|---|
| `App` | 0 | `settings.json` | `AppSettingsService` |
| `Launcher` | 1 | `launcher-settings.json` | `LauncherSettingsService` |
| `AirApp` | 2 | `airapp-settings.json` | `SettingsService` 的 AirApp section |
| `ComponentInstance` | 3 | SQLite `component-state.db`（表 `component_state` / `component_message`） | `ComponentDomainStorageProvider` |

统一入口是 `Services/Settings/SettingsService.cs`，它按 scope 分派到上面四处。数据根是 `%LocalAppData%\LanMountainDesktop`，可被 `--data-root` / `LMD_DATA_ROOT` 覆盖。

## 2. 读写策略

| 方面 | 实际行为 |
|---|---|
| 写盘 | **没有防抖**。写入即刻原子写（`AtomicFileWriter.WriteText`） |
| 读盘 | 400ms 快照缓存窗口（`SettingsSnapshotCache`） |
| 跨窗口同步 | 各窗口订阅 `ISettingsService.Changed` 自行刷新 |
| 跨进程同步 | **靠磁盘写时间探测**（`File.GetLastWriteTimeUtc` + 缓存判据），没有 IPC 通知 |

"没有防抖 + 400ms 读缓存"这个组合是有意的：写入要立刻持久（避免丢配置），读取要挡住高频访问。但这也意味着**写频繁的代码会频繁落盘**——需要节流的地方由调用方自己负责。

跨进程只靠文件时间戳，所以要特别注意：外部进程改了 `settings.json` 之后，本进程的缓存窗口内可能仍读到旧值。设置窗口的 `OnAppSettingsSaved` 就是为这条设计的刷新钩子。

## 3. 变更通知

```
SettingsService.SaveSnapshot / SaveSection / SetValue
  → OnChanged(new SettingsChangedEvent(scope, subjectId, placementId, sectionId, changedKeys))
  → ISettingsService.Changed（EventHandler<SettingsChangedEvent>）
```

**`SettingsChangedEvent` 是 `Changed` 事件的事件参数，不是消息总线消息。** 它不会出现在 `context.MessageBus` 上——轻应用要观察设置变化，必须从句柄容器解析 `ISettingsService` 并订阅 `Changed`（见 [设置系统（开发者视角）](../01-AirApp开发/02-核心概念/03-设置系统.md)）。

退订有收口工具：`Services/Settings/SettingsChangedSubscription.UnsubscribeOnce`，用 `ref bool` 保证只退一次。**订阅设置事件的地方都应该走它**，否则重复退订或漏退订都会出现。

## 4. 分类目录与设置页注册

```
SettingsCatalogService          定义 section 列表（内置 + 轻应用注册/移除，按 SortOrder 排序）
SettingsPageRegistry.Rebuild    扫描设置页并排序
```

`SettingsPageRegistry` 扫描宿主程序集里所有带 `AirAppSettingsPageInfoAttribute` 的 `AirAppSettingsPageBase` 子类。**新增一个设置页的做法**：写一个继承 `AirAppSettingsPageBase` 的类 + 标注 `[AirAppSettingsPageInfo(id, name, category, ...)]`，不需要改注册表代码。

分类取值 `AirAppSettingsPageCategory`：`General` / `Appearance` / `Components` / `AirApps` / `AirAppCatalog`（旧值 `AirAppMarket` 已废弃）/ `About` / `Dev`。

**排序规则**：内置页用 `pageInfo.SortOrder`；轻应用注册的页排在 `100+`；旧式 section 排在 `200+`。

**门控**：`Dev` 分类只在 `IsDevModeEnabled` 为真时出现。

## 5. 历史迁移

迁移统一走 `AppDataPathProvider.TryMoveLegacyPath`——**只改名、不合并**；两侧同时存在时告警而不是猜。

| 旧 | 新 | 位置 |
|---|---|---|
| `plugin-settings.json` | `airapp-settings.json` | `SettingsService` 构造时先归位 |
| 市场目录 `PluginMarket` | `AirAppMarket` | `AppDataPathProvider` |
| 桌面板布局 `fused_desktop_layout.json` | `desktop_panel_layout.json` | `DesktopPanelLayoutService`（含旧字段导入） |
| `settings.json` 旧键 `LegacyDisabledPluginIds` / `LegacyDevPluginPath` | 合并进新键并清别名 | `AppSettingsService` |
| 布局 JSON（`desktop-layout-settings.json` / `component-settings.json`） | SQLite | `ComponentDomainStorage`，标记 `component_domain_v1` |

迁移的通用规则：**相对路径的归位要在"路径计算出口"做一次，而不是散在每个调用点**。`GetPendingDeletionFilePath` 就是照这个原则写的（注释里记着"散点插迁移必有漏径"）。

---

## 6. 数据位置模式

数据根有两种模式：**系统位置**与**便携位置**，整目录迁移由启动器的 `Infrastructure/DataLocationResolver.cs` 负责（OOBE 时询问，之后也可迁移）。宿主只读 `--data-root` / `LMD_DATA_ROOT`，不自己决定位置。

---

## 7. 轻应用能拿到的设置服务

轻应用容器注册了这些宿主设置服务，其余宿主内部服务不可见：

| 服务 | 用途 |
|---|---|
| `ISettingsService` | 读写 + `Changed` 事件 |
| `ISettingsCatalog` | 分类目录 |
| `ISettingsFacadeService` | 分域设置门面 |
| `IAirAppSettingsService` | 已绑定到本轻应用 id 的作用域设置 |

注册点在 `AirAppLoader.CreateServiceCollection`（经 `RegisterHostService<T>`）。

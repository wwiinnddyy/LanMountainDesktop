# 主题系统

本文讲组件如何**正确适配主题**，以及主题在代码里到底怎么实现。

**键名与数值以 [设计 Token 与资源真源](00-设计token真源.md) 为准**；本文不复制色值表。

> **本文已按代码更正**：旧版描述的 `Themes/LightTheme.axaml`、`Themes/DarkTheme.axaml`、`Themes/Common.axaml` 目录结构在仓库里**不存在**；`CardBackgroundBrush`、`AccentBrush`、`SuccessBrush`、`DesktopBackgroundBrush` 等一批键**也不存在**；`IThemeService`、`ThemeChangedEventArgs`、`Theme` 枚举同样不存在。
> 本项目没有"亮/暗两套静态资源字典"，而是**运行时派生的自适应画笔**；另有 FluentAvalonia 提供的 `TextFillColor*` / `SystemFillColor*` 一族键可用（详见 [真源文档](00-设计token真源.md)）。

最后核对：2026-11-14。

---

## 1. 主题模型

阑山桌面的视觉不是"两套颜色表"，而是：

```
系统主题变体（亮 / 暗 / 跟随系统）
        +
材质色 / 壁纸种子（MaterialColorService）
        ↓
ThemeColorContext + ColorMath 计算
        ↓
AdaptiveBrushFactory 生成画笔
        ↓
注册成 27 个 Adaptive* 资源键
        ↓
组件用 {DynamicResource <键>} 取用
```

因此有两个结论：

1. **不存在固定的亮/暗色值表。** 同一个键在换材质色或换壁纸后取到的颜色不同。想"照着色值抄"是不可能的。
2. **键名必须逐字正确。** 写错不报错，只是那块 UI 静默失色。

### 代码分布

| 内容 | 位置 |
|---|---|
| 自适应画笔键名 | `Theme/ThemeResourceKeys.cs`（27 个，唯一真源） |
| 画笔生成 | `Theme/AdaptiveBrushFactory.cs` |
| 取色口径 | `Theme/AdaptiveTokens.cs` |
| 色计算与调色板 | `Theme/ColorMath.cs`、`Theme/AppThemePalette.cs`、`Theme/ThemeColorContext.cs` |
| 样式与圆角 | `Styles/GlassModule.axaml` 等 |
| 动效时长 | `Styles/FluttermotionToken.axaml` |

**没有 `Themes/` 目录**：样式在 `Styles/*.axaml`（经 `App.axaml` 的 `StyleInclude` 引入），主题逻辑在 `Theme/*.cs`。

## 2. 在组件里怎么用

### 2.1 取色：只用真源里的键

```xml
<Border Background="{DynamicResource AdaptiveSurfaceRaisedBrush}"
        BorderBrush="{DynamicResource AdaptiveGlassPanelBorderBrush}"
        BorderThickness="1"
        CornerRadius="{DynamicResource DesignCornerRadiusComponent}">
  <StackPanel>
    <TextBlock Text="标题" Foreground="{DynamicResource AdaptiveTextPrimaryBrush}"/>
    <TextBlock Text="描述" Foreground="{DynamicResource AdaptiveTextSecondaryBrush}"/>
    <Button Content="操作"/>
  </StackPanel>
</Border>
```

用 `DynamicResource` 而不是 `StaticResource`——后者在材质色变化时不会刷新。

### 2.2 C# 侧取色

```csharp
if (AdaptiveTokens.TryGet<IBrush>(this, ThemeResourceKeys.TextPrimaryBrush, out var brush))
{
    // 用 brush
}
```

不要自己 `TryFindResource`，也不要只看某一本资源字典。历史上宿主里有 5 份各自为政的实现，症状是"同一个键 A 处取得到、B 处取不到，且静默失色"。

### 2.3 接主题变更

**宿主内组件**：订阅宿主外观服务的变更事件（`IAppearanceThemeService` / `IMaterialColorService` 暴露的事件），在回调里重新取色。

**轻应用组件**：用 SDK 给的外观上下文，它在主题或材质色变化时会推送新快照：

```csharp
public sealed class ThemedWidget : UserControl
{
    private readonly IAirAppAppearanceContext _appearance;

    public ThemedWidget(AirAppComponentContext context)
    {
        _appearance = context.Appearance;
        _appearance.Changed += OnAppearanceChanged;
    }

    private void OnAppearanceChanged(object? sender, AppearanceChangedEvent e)
    {
        // 快照已更新，可以直接读
        var snapshot = _appearance.Snapshot;
    }

    // 圆角一律通过它解析，不要硬编码
    private double Radius => _appearance.ResolveCornerRadius(AirAppCornerRadiusPreset.Component);
}
```

轻应用**不要**去调 `Services.GetService<IThemeService>()`——没有这个接口。

**订阅了就要退订**：`Changed` 是裸事件，不退订会让控件无法被回收（影响卸载时的 ALC 回收）。

## 3. 图标与图片适配

图标优先用图标库（FluentIcons / Material.Icons），它们跟随 `Foreground`，自然适配主题：

```xml
<fi:SymbolIcon Symbol="WeatherSunny" Foreground="{DynamicResource AdaptiveTextPrimaryBrush}"/>
```

**图片是最容易翻车的地方**：一张写死的白底/黑底 PNG 在另一档主题下会看不见。

- 优先用矢量（`Path` / `Geometry`）而不是位图
- 必须用位图时，准备明暗两套并在运行时按主题变体切换，或用带透明度的中性色图
- 不要在图片里烘死背景色

## 4. 自定义配色

组件的配色**不应该自己定义一套**。要表达不同观感时：

1. 用不同的语义键组合（`SurfaceBase` / `SurfaceOverlay` / `SurfaceRaised` 表达层级）；
2. 用已有表面类（`glass-panel`、`surface-translucent-*`、`surface-solid-strong`）；
3. 需要强调时用 `AdaptiveAccentBrush` / `AdaptiveTextAccentBrush`，不要在它旁边再定义第二套强调色。

**新增全局键要走注册方与消费方两侧**：键名只认 `ThemeResourceKeys.cs`，注册由主题色系统负责。2026-10-25 的清理删掉了 28 个"只写不读"的键（键数 55 → 27），所以别再造无人消费的键。

## 5. 测试清单

主题相关的问题**只有肉眼能发现**（写错键不报错），所以必须真的过一遍：

**颜色**
- [ ] 全组件用 `{DynamicResource Adaptive*}`
- [ ] 键名逐字对照真源清单，无自造键
- [ ] 亮色档显示正常
- [ ] 暗色档显示正常
- [ ] 切换材质色后显示正常
- [ ] 文字对比度在实渲染结果上达标（≥ 4.5:1 正文 / ≥ 3:1 大字）

**形状与图标**
- [ ] 根容器用 `DesignCornerRadiusComponent`，无硬编码圆角
- [ ] 图标用图标库或矢量，跟随 `Foreground`
- [ ] 位图在明暗两档都可见

**动态**
- [ ] 主题切换时不需要重启就刷新（用了 `DynamicResource`）
- [ ] 订阅了外观/主题事件的控件正确退订

## 6. DO / DON'T

```xml
<!-- ✅ 用真源里的自适应键 -->
<Border Background="{DynamicResource AdaptiveSurfaceRaisedBrush}">
  <TextBlock Foreground="{DynamicResource AdaptiveTextPrimaryBrush}"/>
</Border>

<!-- ❌ 硬编码颜色 → 不响应主题与材质色 -->
<Border Background="#FFFFFF"><TextBlock Foreground="#1C1C1C"/></Border>

<!-- ❌ 自造键名 → 静默失色，不报错 -->
<Border Background="{DynamicResource CardBackgroundBrush}"/>

<!-- ❌ 用 StaticResource → 主题或材质色变化时不刷新 -->
<Border Background="{StaticResource AdaptiveSurfaceRaisedBrush}"/>

<!-- ❌ 烘死背景色的位图 → 在另一档主题下看不见 -->
<Image Source="avares://MyAirApp/Assets/white-card-bg.png"/>
```
